# 网页视频下载器

Windows 本地视频下载工具，用于验证“粘贴网页链接、选择真实可用画质、下载并检查文件”的完整流程。当前适配范围为央视网、好看视频、抖音、B站和AGE动漫。优酷适配已暂时移除。网站列入目标范围不代表其全部视频都可下载。

## 使用

1. 解压整个发布文件夹，双击 `WebVideoDownloader.exe`。保留同目录的运行文件，不要只复制主程序。
2. 粘贴视频网页地址或包含链接的分享文案，解析可用画质。
3. 选择画质和保存目录，开始下载。默认保存到 Windows 当前用户的“下载”文件夹下的 `WebVideoDownloader` 子目录。
4. 等待下载与校验完成，再打开文件所在文件夹。下载期间可以取消任务。
5. 需要登录时打开“账号与扫码登录”，选择对应网站，在官方登录页面完成扫码、短信或其他验证，再使用当前会话重新解析视频。

## 账号与画质

- 各网站使用独立会话。默认仅在本次运行中使用；“记住登录”默认关闭。
- 启用记住登录后，会话使用 Windows DPAPI 在本机加密保存；可以在账号管理中清除。
- “会话已导入”只表示取得会话数据。账号是否有效、是否有会员资格、能取得哪些画质，需要实际解析视频确认。
- 已有会员权益不等于任意会员视频都能导出。DRM、地域限制、验证码、过期链接和网站接口变化都可能影响结果。
- 分辨率描述视频文件尺寸。平台提供的 1080p 文件也可能使用原本模糊的监控素材。

## 本次使用的样本

- 央视网：`https://tv.cctv.com/2018/08/10/VIDEQ6OJXSs99b8GFIAQ45YP180810.shtml`
- 好看视频：`https://haokan.baidu.com/v?vid=6165840185958740297`
- B站：`https://www.bilibili.com/video/BV1bK411W797`

央视样本已在原型下载流程中验证为 720p，好看样本为 1080p，B站样本为 720p，三条均通过全片解码检查。央视还通过了实际主界面按钮操作的解析、选择、下载与保存检查。

## 从源码运行

在项目目录使用 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe prepare_tools.py
.\.venv\Scripts\python.exe main.py
```

`tools` 存放随包运行的 FFmpeg、ffprobe、Node.js 及所需 DLL；`vendor` 存放央视专用格式处理依赖。仅安装 Python 包不能替代这些文件。

构建 Windows 发布目录：

```powershell
.\build.ps1
```

构建完成后运行 `dist\WebVideoDownloader\WebVideoDownloader.exe`。

## v0.2.0 正式发布

主程序更名为 `WebVideoDownloader.exe`。下载发布页的 Windows x64 ZIP 后解压整个目录，再运行主程序。

侧栏“检查更新”读取本仓库的正式 GitHub Release。公开仓库无需 GitHub 登录、令牌或 GitHub CLI，直接检查和下载更新。发现新版本后可下载完整包，校验大小及 SHA-256，关闭旧程序后替换程序运行文件；替换或启动失败时恢复旧版。下载目录和本机登录会话保留，程序目录中的额外用户文件也保留。旧程序运行文件备份在程序目录旁的 `.backup-` 文件夹。安装目录需要当前用户有写入权限。

旧版 0.1.x 没有在线升级入口，第一次需要手动下载此版本；从此版本起可在软件里检查更新。GitHub 网络不可用时会明确提示，可以稍后重试或手动下载。源码模式可检查更新，但不会覆盖源码安装。

### 适配列表维护

`sites.json` 是正式适配器、显示名称、域名、验证情况及适配日期的唯一登记处。新增适配器后在此登记 `handler`（`模块:函数`）；构建时自动填入缺失的首次适配日期，列表自动显示，无需再修改界面。只有通过完整下载校验的通用新站点，才会自动追加到本机适配记录，并标注“曾成功下载，其他内容需验证”。正式登记会优先于本机记录。

### 发布流程

构建后运行 `python package_release.py` 生成带版本号的 ZIP、`SHA256SUMS.txt` 和在线升级清单 `update.json`。发布 GitHub Release 时必须同时上传这三个附件，并保持版本标签、程序版本和升级清单一致。

## v0.3.0 断点续传

- 下载中点击“暂停”，已下载内容会保留；点击“继续”恢复。
- 关闭软件会先暂停当前任务。重新打开后，在侧栏“下载任务”中选择任务并继续；恢复前重新解析媒体地址，账号仍需具有相应权限。
- “取消并删除”停止当前任务并删除该任务缓存；任务列表中也可删除已暂停任务。已有成品和其他任务不会删除。
- 直链按服务器返回的 ETag / Last-Modified 和 HTTP Range 续传；服务器不支持可靠续传或返回完整文件时，会提示并重新下载当前文件。错误范围或源文件参数变化会停止，避免错误拼接。
- B站等 yt-dlp 下载保留原有分片与 .part 状态；央视高清复用完成的分片；抖音图文复用已完成原图和配乐。封装、图文合成和完整性校验阶段暂停后，会重新执行当前处理阶段。
- 任务记录存放于本机应用数据目录；缓存位于原下载目录内的 `.video-downloader-<任务编号>`。请保留原下载目录，移动或手动删除缓存会导致无法复用进度。记录仅保存作品页面、画质、目录和状态，不保存 Cookie 或临时媒体链接。
- 只支持本版本创建的任务；历史版本已经删除的临时下载无法恢复。已知特殊央视分片格式或分片列表变化时会保留任务并提示，不会错误拼接。

## v0.4.0 下载队列与设置

点击下载会先保存任务，播放入队动画，再清空链接和作品画质信息；保存目录保留，可继续解析其他链接。右上角“⚙ 设置”可将并行数设为 1～10，默认 5，重启后保留。超过上限的任务排队。并行槽位包含地址准备、下载、封装和校验；降低上限不强制中断运行中的任务。

“下载任务”窗口实时刷新，显示作品、进度、网站、状态和完整保存路径，长路径支持横向滚动。直链和已知总量的音视频按字节计算下载百分比；分片和图文按完成项计算。未知总量会明确显示。100% 表示下载阶段结束，封装/校验仍单独显示；校验通过才标记完成。暂停和重启后保留最近一次进度快照，已完成记录在本次会话保留。任务窗口可独立暂停、继续、取消删除，关闭该窗口不影响下载。关闭主程序会暂停运行和排队任务，重启后手动继续。

AGE 复用刚解析出的有效媒体信息，地址失效后刷新一次。播放器提供可靠的时长和尺寸时复用其元数据，避免再次远程探测；不足时仍通过 ffprobe 探测。下载后保留本地音轨、尺寸、时长及全片解码校验。各站访问和网络状况仍会影响等待时间。

### v0.4.1 状态提示

音视频下载到 100% 后，内部合并阶段也明确显示正在处理，直到全片校验通过才标记完成。

## v0.4.2 更新限流修复

检查更新优先读取 GitHub API；限流、服务端错误或接口连接失败时，自动从公开 Release 的 latest 跳转确认版本，再读取固定版本的 update.json 和 ZIP。全过程无需认证。备用路径同样验证仓库、版本、文件名、大小、SHA-256 和解压路径，不会绕过校验。更新窗口增加“打开发布页”，供两条网络路径都不可用时手动下载。

旧版遇到限流无法自行取得此修复，需要先从 Release 页面手动下载完整 v0.4.2 ZIP，关闭旧程序后完整解压运行；保留原下载目录与任务缓存。换到此版后，API 再次限流会自动尝试公开发布路径。

## v0.5.0 任务界面与长期历史

下载任务提供“全部／进行中／已完成／已取消”分组，进行中包含运行、排队、暂停和失败任务。搜索框在当前分组内匹配作品名、网站和保存路径，刷新进度时保留搜索与选中任务。

作品标题单行显示，超长省略并悬浮查看全文。作品与路径列随窗口增宽分配空间；超长路径仍保留横向滚动和完整内容。

完成与取消记录从本版本开始长期保存，重启后仍可查询，元数据位于应用数据目录 download-tasks/history。旧版未完成任务和缓存保持兼容；此前已丢失或仅留在旧版内存中的历史不自动补回。

“取消下载”先停止任务、清理该任务缓存，再归档为已取消；已取消任务不能直接续传。历史页的“删除记录”只删记录，不删除成品文件。任务完成需要通过原有下载完整性校验；下载达到 100% 但仍在处理的任务继续归入进行中。历史单条损坏会隔离处理，不影响其他任务。

### v0.5.1 删除范围与进度显示

任务进度条及百分比在单元格中居中。“进行中”不显示历史删除按钮；“全部”选中未完成任务时同样隐藏，但暂停、继续、取消下载仍保留。

历史任务的“删除…”会弹出范围选择，默认仅删除记录，也可选择删除记录及该任务临时缓存，两种方式均保留记录对应的 MP4/ZIP 成品。只清理工具为该任务建立的缓存目录；清理失败时保留记录便于重试。如果检测到成品位于缓存目录内，会停止清理并提示改选仅删记录。已取消任务通常已无缓存，选择清理不会影响其他任务。

### v0.6.0 任务勾选与批量操作

任务列表使用勾选框执行批量暂停、继续、取消和删除历史。全选只作用于当前分组与搜索结果；切换分组或搜索会清空勾选，进度刷新保留勾选。已完成页“清除下载记录”仅操作勾选项，未勾选时禁用。删除默认仅删记录，可选清理任务缓存，均保留成品文件。确认弹窗固定操作 ID，并显示提交、跳过、失败数量；需官方验证的抖音任务依次处理，不覆盖主界面解析结果。

### v0.6.1 在线更新下载恢复

修复更新包传输中断后不能恢复的问题：连续 5 秒无数据自动重连，最多 4 次连接；重试或取消后保留进度，再次更新续传同一校验标识的包。显示下载量、速度、重试和校验阶段。服务器不支持续传时重下，错误 Range 拒绝拼接，始终校验完整 SHA-256 后才安装。旧版本首次升级仍运行旧更新器，必要时手动安装本版。

### v0.6.2 下载任务状态显示

状态列按内置最长显示文案的字体像素宽度设置默认宽度。恢复下载简写为“确认已下载进度”，悬停和日志保留完整文本。超长状态或手动缩窄时省略并裁剪到单元格内，避免覆盖保存位置；刷新保持列宽稳定，窄窗口可横向滚动。

### v0.7.0 日志与故障反馈

侧栏“日志与故障反馈”支持后台导出脱敏 ZIP，以及打开预填 GitHub Issue 页面（自行添加 ZIP 附件并确认提交）。运行日志默认开启，每份最大 5 MiB，总计最多 5 份。主界面连续 15 秒无心跳时由独立监测进程记录疑似卡死；后台采样记录线程堆栈，解释器整体阻塞时可能是阻塞前最后一次采样，报告会说明。异常退出/卡死后，下次启动可提示导出。

本地诊断目录位于 `%LOCALAPPDATA%\WebVideoDownloaderPrototype\diagnostics`。只收集白名单日志和诊断元数据；Cookie、会话、浏览器资料、媒体及完整内存转储不打包。链接、路径和凭据在写入前及导出时脱敏；默认没有自动上传。写入失败不影响下载，窗口显示记录可用状态，导出失败给出提示。原 AGE 卡死仍需现场证据，新增诊断能力不等同于已修复该卡死。

### v0.8.0 托盘、速度和悬浮框

下载任务默认显示进行中，分组依次为进行中/已完成/全部/已取消。速度列与主界面、任务窗口的整体速度共用有效传输数据；停止、处理及过期样本不计速度。本轮进度仅统计当前提交队列及该轮已完成任务，按可靠总字节加权，未知总量如实显示；新增/取消会调整范围，不混入全部历史。

主窗口 × 首次询问隐藏到托盘/退出/取消，可记住选择，设置可更改。隐藏继续下载，退出暂停并保留续传。托盘不可用时不隐藏；托盘菜单可恢复窗口、打开任务、切换悬浮框及显式退出。在线安装更新绕过关闭询问和隐藏选项。

悬浮框默认关闭，设置中可开启并调整不透明度（默认 85%），每 3 秒轮播概况与正在传输的任务。拖到左右屏幕边缘吸附，移开鼠标 1 秒收起，悬停展开，拖离恢复；可关闭自动收起。右键关闭同步设置，重启保留开关、位置和不透明度，显示器移除后恢复到可见工作区。退出主程序保留悬浮框开启偏好。

### v0.9.0 更新中心与增量更新

- 默认启动 15 秒后检查更新，距上次成功检查不足设置间隔时跳过；运行及托盘期间默认每 4 小时检查，可在设置中关闭或调整为 1～168 小时。退出后停止。
- 发现新版时侧栏显示红点和版本，同一版本提醒一次；打开更新中心不会清除红点。支持稍后 4 小时提醒、忽略此版本，未来版本仍正常提示。只自动检查，不自动下载安装；下载任务进行时可以查看更新，安装须等任务结束。
- 更新说明支持 Markdown 标题、列表、粗体、表格和链接，不加载远程图片。更新中心显示目标版本、日期、包类型与下载大小。
- 发布最近 3 个基线到最新版的文件级增量包。本地完整性通过校验时优先增量；原生运行库变化、数据兼容变化或发行策略要求时全量更新并显示原因。缺少增量或本地文件被修改时先询问是否全量。两种包均支持续传、重试和完整 SHA-256 校验。
- 安装先组装并校验完整程序，再按清单备份、替换和清理废弃程序文件；失败恢复原文件。仅保留一份受管理的上一版备份；未知文件不删除，旧版本产生的无归属备份不会自动清理。
- “历史版本 / 回退”提供最近 3 个兼容稳定版；优先恢复有效本地备份，否则下载完整包；降级前需确认。设置先备份，账号、下载文件及任务记录不回退。不兼容或撤回版本不可选；回退后忽略刚离开的版本，仍检测未来修复版本。
- 程序目录中的 **修复与回退.cmd** 不依赖主 EXE 或 Qt，可以离线恢复备份或在线选择完整历史包。若主程序首次启动失败、尚未创建根目录入口，可使用 `_internal\recovery.cmd`。修复前先退出下载器；无响应时先在任务管理器结束进程。完全丢失安装清单时请解压完整包到新目录。

**首次升级说明：0.8.0 及以前的更新器需要完整下载一次 0.9.0，之后才能使用增量机制。** 可继续自行在线升级，本次不覆盖你的本地测试目录。

发行策略由 `release_policy.json` 配置：`force_full` 只选择完整包，不会强制用户安装；`revoked_versions` 禁止对应版本在线回退；数据兼容版本改变时会禁用不兼容历史版。运行 `package_release.py` 生成完整 ZIP、文件清单、最近三基线增量、历史目录和 SHA256SUMS，全部发布到同一 GitHub Release。版本标签的附件发布后不要替换，以保持续传和哈希固定。
