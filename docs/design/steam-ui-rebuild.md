# Steam 界面重构执行规格（#27）

本轮的交付状态是“实现并完成自检，等待用户整体验收”。用户认可前不关闭 #27。

## 参照与边界

用户提供的原版截图保存在 `steam-reference/`：library、downloads、details、storage。它们只作为设计和测试参考，不随程序发布，不将 Steam 游戏、账号、商店或社交功能加入下载器。保留 PySide6、便携数据和全部现有业务。

主要可观察入口为真实主窗口及其弹窗；复用现有业务与 Qt 界面测试。视觉与业务结论分开记录。

## 比例与层次

- 原版 2560 像素截图：顶部 78，底栏约 49，侧栏约 360。参考的是 Windows 缩放后的客户端观感，不能把整个界面按图片宽度等比缩小。
- 常规桌面窗口：两行顶部合计约 76–82 个逻辑像素，侧栏初始约 260–300，可调整；底栏约 38–44。字体保持正常阅读尺寸，主导航约 20px，正文约 13px，辅助信息约 11–12px。
- 顶部、底部最暗；侧栏略亮；库内容为中灰蓝。顶层区域之间以边界和色差区分，不以一圈圈表单边框区分。
- 内容以横向陈列架、分类标题、细分隔线、稳定的 2:3 封面组织。去除旧版无内容的巨大蓝色矩形。
- 详情为大幅横图、主要动作栏、信息/选集区。播放器调用、逐季确认、下载勾选规则不变。
- 下载为宽行列表与醒目的总体速度趋势区域；保留分组、搜索、勾选和全部批量操作。状态及路径仍可查看。
- 设置/存储空间采用左侧分类、右侧内容；真实磁盘可用空间不伪造成应用自身占用。

## 迭代验收矩阵

| 场景 | 必须观察 | 业务验证 |
| --- | --- | --- |
| 空库 | 完整外壳、可理解的空状态、明确添加入口 | 添加/导入可达 |
| 有内容库 | 图标侧栏、封面陈列架、排序、悬停与选中 | 搜索、筛选、进入详情 |
| 季详情 | 横图、动作栏、选集和状态 | 分页、选择、播放确认、来源 |
| 下载任务 | 曲线、宽行、速度/进度、分组和操作 | ID 稳定、批量暂停/继续/取消/删除 |
| 设置/存储 | 分类和空间条、路径、播放器 | 保存、增删存储库的既有限制 |
| 小窗口/150% | 标题不顶出、侧栏/内容可滚动、无不可达操作 | 与正常尺寸一致 |
| 实际 EXE | 与源码一致的页面和主题 | 正常启动、退出、核心交互 |

截图必须来自实际 Qt 窗口，保留参考、修改前和修改后。固定演示数据只在隔离目录创建，不写入用户数据，不包含账户 Cookie，不随程序发布。使用参考截图中的封面裁切时只用于布局对照，不作产品内置素材。

## 自主推进

按 #28–#32 的依赖推进。实现 → 启动 → 截图 → 差异记录 → 修正 → 回归，直到不存在已知且可修正的明显差距。常规设计选择自主处理，关键外部阻塞才询问用户。代码审查与截图检查分别执行；不得编造相似度评分。

每次阶段结束将结果与下一步写回 Issue。发布包是供验收的版本，不代表用户已经验收。
