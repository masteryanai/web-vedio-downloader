# 影片库与 Steam 风格 UI 重构方案

状态：15 项产品决定已确认，用户已授权执行。由 #26 统一跟踪，关联 #3、#6、#21。

## 1. 产品结构与视觉

继续使用 PySide6 / Qt Widgets。整体参考 Steam 桌面客户端的库与下载管理：深灰蓝分层、青蓝高亮、顶部主导航、左侧分类、中央内容和底部下载状态条。保留本工具的名称与功能含义。

- 启动默认打开影片库；影片库、季详情和下载任务在同一主窗口切换。
- “添加影片”打开弹窗，一次完成链接解析、季归属、选集、画质、存储库选择和加入队列。
- 设置、账号、更新及故障反馈从统一入口打开；已有能力保持可达。
- 托盘、悬浮框及独立安装窗口保留；独立安装窗口继续在主程序退出后运行。
- 首版深色主题，支持 Windows 高 DPI 和窗口缩放；缩小时减少封面列数、收起详情侧栏，列表可滚动，主要操作可达。

## 2. 库、作品与选集

| 概念 | 含义 |
| --- | --- |
| 影片库 | 所有已入库作品的统一目录视图，跨磁盘浏览 |
| 存储库 | 用户配置的实际媒体保存目录，可有多个磁盘位置 |
| 季条目 | 一个可独立进入详情页的管理单位；同作品不同季分别入库 |
| 选集 | 季下可单独下载、重试、定位与播放的集 |
| 来源 | 网站及其作品/季/选集标识；同一季可经确认关联多个来源 |
| 外部文件 | 导入前已存在、保留原路径管理的媒体文件 |

- 小封面卡片显示作品名、季名及下载数量；季详情展示大封面和选集状态。
- 单部电影和普通视频独立入库，不强制建立“第一季”。
- 季信息不可靠时显示待确认，由用户填写季名或归入已有季。播放线路、画质版本和 URL 数字不能直接当作季。
- 抖音图文独立入库：可保存原图或合成配乐视频；原图提供打开图片文件夹，视频提供播放；图片不是剧集。

## 3. 添加与批量下载

流程：添加影片 → 粘贴播放链接或分享文案 → 解析 → 若有合集则显示选集 → 确认季归属、存储库与画质 → 加入库并下载。

- 检测到多集时直接在同一弹窗展示合集，不让用户逐集复制链接。
- 默认勾选未下载集，已下载集默认跳过；支持全选未下载、全不选和手动勾选。
- 同一季的新增下载使用一个存储库；不同季可选不同磁盘。界面展示实际保存目录，例如 `D:\影视库\作品名\第一季`。
- 画质优先策略：没有目标档位时默认选择最高较低可用画质，并在任务中标明；可选择严格模式，缺失则跳过并汇总提示。
- 已下载集默认不覆盖；重复加入不能产生无意义重复任务。
- 沿用现有下载并行、续传、限速和完成校验能力。已有默认并行 5、最大 10 的配置保持。
- 批量列举与封面获取是逐站适配能力，不能把“能下载单集”当作“能列举全季”。无法识别时仍保留单集下载，不伪造合集。

## 4. 重复识别与来源

- 首先按同网站、同作品/季、选集标识匹配，再检查记录对应的本地文件是否仍存在。
- 跨网站同名作品不自动合并。用户确认归入同季时，还需确认选集对应关系和默认下载源，保留原来源信息。
- 来源失败时提示重试或切换；不静默换源，不覆盖现有视频。
- 在线存储中找不到文件，显示缺失并提供重新定位/下载入口；整个磁盘离线时标注离线，不据此清除选集或误判为文件已删除。

## 5. 存储、导入与文件操作

- 设置支持新增、选择和管理多个存储库路径。
- 旧下载记录及用户选定文件夹支持导入预览，展示拟归属的作品、季、选集及不确定项，确认后入库。
- 不自动扫描整盘，不自动移动或重命名旧视频。外部文件可散落多个目录，不受新增下载集中存储规则强制整理。
- 磁盘离线、空间不足时提示处理，不自动换盘或迁移。跨库整理/迁移为用户单独发起的操作。
- 移除库记录默认保留媒体。“删除本地视频”为单独操作，确认范围；外部文件默认不参与删除。
- 界面需区分已下载、未下载、传输、排队、处理、暂停、失败、文件缺失和磁盘离线。
- 沿用便携数据规则：软件设置、索引等在程序 `data`，软件更新缓存在 `update`；媒体由所选存储库或原文件位置管理，不新增 C 盘备用大缓存。

## 6. 播放、封面与新集

播放使用系统默认外部播放器，设置允许指定播放器。选集只有已下载且文件存在时可播放；默认先确认。

**“以后不再提示”只作用于当前季**，不影响其他季。确认框明确写“播放本季其他选集时不再提示”。单部作品的免提示不能误扩展至其他作品。调用外部播放器不等于能够获取可靠观看进度，首版不承诺断点观看或自动连播。

封面优先读取原站小图和作品级大图，尝试获得合适尺寸；大图缺失时用站点占位。允许本地图片或图片链接手动更换，不自动搜索第三方影视资料站。

季详情提供手动刷新选集与封面。新集定时检查逐季可选，默认不自动开启；发现新集只提示，不自动下载。登录失效或检查失败时保留已知选集和文件状态。

## 7. 下载任务与 #21

- 下载任务页保留分组、搜索、复选及既有批量操作，加入整体速度、进度和短期速度趋势图。
- 底部状态条贯穿主窗口，点击进入下载任务。
- 全部成功完成后显示完成 3 秒，再恢复空闲；计时不因刷新重置，新活动立即终止旧完成提示。
- 当前关注任务完成、其他工作仍进行时显示整体状态。排队、解析、封装、校验不误报空闲；暂停/失败分别显示数量。
- 历史记录与日志保留；实时状态复位不等于删除历史。
- 悬浮框透明四角、单层圆角；保留总速度/总进度/各进行中速度轮播，以及拖动、靠边收起、不透明度和托盘操作。

## 8. 实施分段与验收

1. 建立存储库、季/选集/来源/本地文件索引和兼容旧记录的导入预览。
2. 实现已适配网站的合集识别与批量队列，验证去重、画质策略、失败与缺失边界。
3. 接入影片库、季详情和添加弹窗；统一主窗口导航、设置入口、播放和封面。
4. 整合下载任务、速度趋势、悬浮框和 #21；验证缩放、高 DPI、托盘及独立安装行为。
5. Windows 最终 EXE 集成验证，推送时按项目约定发布对应 Release；在实际原生依赖与数据兼容策略允许时生成增量。

以上为同一整体改造的技术实施顺序，不代表把已确认功能删出范围。正式实施前将本方案落到总 Issue，关联 #3/#6/#21，记录各站合集能力和验收结果。

验收至少覆盖：跨磁盘库、季独立入口、旧文件原位导入、多集跳过已下载、丢失与离线区分、季归属确认、跨站映射、画质降档/严格模式、季级免播放确认、图文两种输出、封面替换、新集仅提示、文件删除范围、#21计时与轮播、窗口缩放及真实Windows EXE。

首版不纳入：浅色主题、内置播放器、自动第三方封面搜索、自动跨站合并/换源、自动下载新集、观看进度同步和自动连播。
