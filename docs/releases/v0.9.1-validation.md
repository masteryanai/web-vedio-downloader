# v0.9.1 单实例修复验证（#18）

根因：GUI 启动直接创建 Window/DesktopController，没有进程锁或已有窗口唤起通道。真实双进程回归在修复前失败：第二次启动创建新主窗口/托盘。

修复：同一用户数据目录使用 QLockFile 原子抢占；锁持有者启动仅当前用户可访问的 QLocalServer。后续 GUI 启动仅请求激活并退出；已有窗口从托盘/最小化恢复，链接与任务不被第二次启动覆盖。主程序会尝试向锁持有者授予前台激活权限。后台诊断 watchdog 和命令行操作不经过 GUI 限制。进程异常退出的残留锁由 Qt 的存活检查恢复；原进程无响应则拒绝新增 GUI。

验证：
- 旧版本真实双进程测试先失败，再由修复通过。
- 82 项回归测试通过，包含托盘恢复、最小化恢复、输入保留、同时启动、崩溃后重新启动。
- 最终 Windows EXE：重复运行、最小化后恢复、不同安装目录共享数据目录、正常退出释放锁全部通过。
- 从冻结档案读取 main 与 single_instance，编译对象与当前源码一致。
- 原有用户测试目录和运行中的旧实例未修改、未强行退出。旧版无唤起协议，首次切换需先正常退出多余旧窗口。

实际 0.9.0 → 0.9.1 增量重建、完整目标哈希、PowerShell 事务安装、升级后 EXE 启动、退出释放实例锁及用户文件保留通过。
