# v0.12.0 便携数据验证（#24）

- 用户确认设置、Windows 加密会话、任务记录、日志和更新状态统一放在程序根目录 `data`，更新大文件仍在 `update`。已下载媒体和任务输出位置保持不变。用户已清除旧 C 盘更新文件，迁移允许其不存在。
- 默认运行路径与账号存储统一，源码/测试可显式设置 `WVD_DATA_DIR` 隔离；不以不可写为由静默使用系统盘。未知 `data` 目录和损坏归属标记拒绝覆盖。
- 一次性迁移使用后台线程，逐文件 SHA-256 和源状态校验；目标冲突另存副本。校验成功后仅清理相同原件，不递归删除旧用户目录。取消、复制失败、源变化、链接与不可写等边界保护数据；失效更新计划保留归档，未知旧缓存保留。
- 旧安装器先启动新 EXE 后才完成结果写入的场景，通过等待旧锁释放来避免抢迁移；检查其他下载器进程，防止迁移活动旧任务。
- 用户级内存互斥与当前用户 IPC 保留跨安装目录单实例，不在 C 盘创建实例锁；检测仍在运行的旧版并尝试唤起。原进程异常退出后互斥可恢复。独立修复默认使用程序 `data`，隔离测试可显式覆盖。
- 完整 `python -m unittest discover -s tests -v` **140 项通过**。便携迁移/界面专项 **18 项通过**：缺失旧缓存、无旧目录、重复启动、冲突、取消/复制失败、晚到修改、不可写、未知归属、损坏标记、失效更新引用、DPAPI 原密文及账号管理器读取、重定位、数据不进入程序清单、链接拒绝、互斥进程崩溃恢复和界面响应。
- Windows PowerShell 安装/修复协议 **18 项通过**，含默认便携数据根且不修改旧用户状态、显式自选缓存、失败回滚、排他安装锁及不兼容旧布局备份不被提供。使用小型隔离程序，不对用户真实程序做安装或额外全量备份。
- 最终 EXE 冻结模块与当前源码逐一核对一致。隔离的旧数据夹放在系统临时目录，程序夹放在 D 盘；运行真实 EXE，验证设置、DPAPI 密文和已完成任务迁移，原旧数据根清理，媒体成品不移动。
- 真实 EXE 打开设置和缓存界面，显示程序目录下 `data`；通过 UI 应用 `update` 缓存目录。最小化后从另一个安装目录再次启动，原窗口恢复，第二目录没有创建 `data` 或新 GUI。
- 退出后重命名完整测试程序目录，再运行同一 EXE；更新缓存归属和配置自动重定位，记住的账号仍可解密，已完成任务仍在，旧 LocalAppData 根未重建。测试中没有接触用户真实账号或现用客户端目录。
- 数据兼容策略升级为 2：首次旧布局到便携布局全量，旧布局历史版与本地备份不直接回退，既有备份不因此删除。以后的同布局版本仍可增量和回退。此限制防止旧版将找不到便携数据误当作账号/任务丢失。
- `data` / `update` 均被 Git 忽略，发行与程序清单只包含受管理程序文件。完整包换新目录必须同时带上现有 `data`；DPAPI 仍绑定 Windows 用户/机器，跨身份不承诺复用登录。
