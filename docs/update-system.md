# 更新系统约定（#17）

本项目是 Windows 客户端，更新安装、托盘、Qt 和独立 PowerShell 维护入口在 Windows 本地验证；无须部署服务器。所有在线元数据和附件来自本仓库公开 GitHub Releases，不需要用户 GitHub 认证。

## 发行资源

`package_release.py` 自动获取最近三次稳定发行的缓存（验证旧包大小与哈希）；离线时可使用三份已验证缓存，缓存不足则报错，避免静默遗漏历史版。`release/` 为本机缓存，不提交 Git。

每次发布包含：完整 Windows ZIP、`update.json`、当前与三个基线的 `inventory-v*.json`、对应的文件增量 ZIP（兼容时）、`history.json`、`SHA256SUMS.txt`。清单保留旧版完整包字段，新客户端识别 schema 2。已发布标签的附件必须保持不变。

- 文件清单包含程序文件的路径、大小与 SHA-256，清单本身的哈希由发行描述固定。
- 增量仅包含新增/变化文件，删除列表必须与前后清单推导结果一致。三条基线分别到目标版本，不串联下载中间版本。
- 原生 DLL/PYD 文件集合或哈希变化、数据兼容版本变化时，该基线自动改为全量。
- `release_policy.json` 的 `force_full`/`force_full_reason` 可显式要求全量；只影响包选择，不强制用户安装。
- `revoked_versions` 禁止相应历史版本在线回退；`data_schema` 不同的历史版不可选。离线备份只能依据本机已缓存的撤回信息判断，离线无法获知刚发生的撤回。

## 安装事务

下载使用固定附件大小和 SHA 标识续传缓存；临时目录组装完整目标并逐文件校验。独立安装器等待主进程退出，拒绝同目录的其他运行实例，并持有排他安装锁。只覆盖目标清单、删除基线废弃文件；根目录其他文件和 `_internal` 内未知文件保留。任务/账号/下载媒体位于原来的位置，不纳入程序事务。

替换前完整备份受管理文件，备份设置；失败逐一恢复已触及文件。正常启动失败也回滚。成功后保留一份受管理备份；清理验证安装目录、备份标记和令牌，只删除已知文件，未知内容及无归属旧备份不删除。准备目录仅清理已验证的程序文件，结果和计划留作排查。

本机记录位于 `%LOCALAPPDATA%\WebVideoDownloaderPrototype\updates`：检测状态、下载缓存、历史目录、备份索引、安装阶段与结果；沿用旧数据目录以保持账户/任务兼容，不改变现有任务格式。

## 恢复边界

历史回退只选择最近三个兼容稳定版，必须确认；优先使用完整本地备份，否则全量，不做反向增量。回退时只备份设置，不回卷任务、账号与媒体，并忽略刚离开的版本，后续新版仍检测。

主程序启动时维护根目录 `.maintenance` 与“修复与回退.cmd”。这些文件在程序清单之外，回退旧版后仍存在；旧版不能降级维护工具。工具依赖 Windows PowerShell/.NET，不依赖主 EXE、Python 或 Qt。首次启动前若根入口未创建，可运行 `_internal\recovery.cmd`。完全丢失安装清单时须将完整便携包解压到新目录。

首次从 0.8.0 及以前升级需全量一次，因为旧客户端不识别新协议。对旧安装器的首次升级兼容已使用真实 0.8.0 安装脚本及最终 EXE 验证。
